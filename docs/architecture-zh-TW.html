Pixel Trigger 專案架構

一個由 Tkinter 控制的本機視覺自動化工具：設定檔把「看見什麼」與「要做什麼」組成 Combo，偵測引擎在背景執行圖片、OCR 與色帶判定，再把安全可取消的輸入動作送回 Windows。

啟動點 main.py UI 主執行緒 偵測 worker 本機 JSON / PNG / CSV 離線 Tesseract
01

主動偵測：從畫面到輸入動作

核心路徑集中在 HookEngine：每一輪只擷取一次畫面，所有啟用的 Combo 共用該 frame，慢規則則交給各自的 worker，避免彼此阻塞。

純 OCR

沒有圖片時，直接對擷取畫面做文字比對。

圖片 + OCR

先定位圖片，再只對命中區域做文字驗證。

位置控制

追蹤色標位置，持續調節按鍵或滑鼠動作。

色帶控制

依色帶狀態與遲滯閾值切換持續動作。

失效即停，不退回全螢幕
  • 視窗關閉、最小化或 PID 改變時停止。
  • 滑鼠按鍵各自有鎖，避免多個 Combo 同時搶用。
  • stop_event 貫穿掃描、等待與輸入動作。
02

背景記帳：獨立的餘額辨識管線

BackgroundCalc 與主動偵測並行但目的不同：它每秒讀取指定 Combo 的餘額，經重複確認後交給 Ledger 寫入每日 CSV。

協調與介面 視覺辨識 動作與持久化 停止與安全邊界
03

執行緒邊界：Tkinter 只留在主執行緒

UI、主動掃描、Combo 判定、持續動作與背景記帳各有清楚邊界；worker 不直接碰 Tkinter，而是回傳輕量訊息。

MAIN THREAD

App / Tkinter

處理按鈕、編輯器、全域熱鍵註冊、日誌與 Debug Overlay。

SCAN THREAD

HookEngine 掃描迴圈

共享 frame、維護上一輪可見狀態，將 Combo 丟進 ThreadPoolExecutor。

COMBO WORKERS

圖片 / OCR 判定

每個 Combo 同時最多處理一張最新畫面；慢規則不堆積舊 frame。

ACTION THREADS

持續輸入與位置控制

條件消失時由專屬事件停止；一次性動作則直接受引擎停止事件控制。

BACKGROUND

BackgroundCalc

每秒擷取、辨識並更新 Ledger，與主動偵測分開啟停。

回到 UI 的訊息橋

回呼把 triggered、cycle、status、背景讀值與錯誤放入 collections.deque。

主執行緒每 150 ms 由 root.after() 清空佇列並更新元件。

04

模組地圖：平坦結構，各檔案一個責任

專案刻意維持平坦模組；資料模型是共同語言，GUI 負責協調，視覺與輸入則分開封裝。

main.py

程序入口

建立 App、註冊熱鍵、進入 Tk 主迴圈。

gui.py

介面與協調器

Profile / Combo 編輯、生命週期、訊息佇列與 Debug Overlay。

automation.py

主動偵測引擎

掃描排程、觸發狀態、動作執行與取消。

screen_capture.py

視覺能力

Pillow ImageGrab 擷取、OpenCV 模板比對、色標 / 色帶與 Tesseract OCR。

input_controller.py

輸入輸出

透過 PyAutoGUI 發送滑鼠、鍵盤與系統音效。

models.py

領域資料

Profile、Combo、Action 與 Enum 的序列化規則。

profile_manager.py

設定持久化

將 Profile 讀寫為 profiles/*.json，管理模板目錄。

calc.py

背景記帳

餘額辨識協調、每日會計日與 CSV Ledger。

window_target.py

Windows 視窗

以 ctypes 列舉視窗，解析有效的 client-area 螢幕座標。

展開：本機資料與建置產物
  • profiles/*.json：使用者自動化設定；不進版控。
  • templates/：觸發與點擊目標圖片；不進版控。
  • calc/*.csv：按日期分檔的餘額異動紀錄。
  • vendor/tesseract/：由 prepare_tesseract.py 產生的離線 OCR runtime。
  • dist/pixel_trigger.exe：由 build.py 建立的 Nuitka 單檔 Windows 執行檔。
  • test_*.py：標準函式庫 unittest 的回歸測試。
